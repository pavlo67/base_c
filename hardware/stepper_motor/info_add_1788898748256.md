# Runner names and live braking pulse budget

The sequence-based free runner is now `executeSequence(sequence, pinStep, pinDir, pinEna, expecterInterval, options, pulseHigh, hardwarePwm, timeLimit, real)`. It executes an existing plan and leaves GPIO lifecycle to its caller. The full-move `run(config, rotationDeg, label, real)` calls `executeSequence()` and owns planning, logging and GPIO lifecycle. Both functions are used: `run()` by Machina/probe_sequences, `executeSequence()` by `run()` and low-level execution tests. `StepperMotorAction::run()` remains the member timer loop. Earlier documentation describing two free `run()` overloads is superseded.

Clocked acceleration plans retain `pairedTargetPulses_`, the combined acceleration/braking pulse budget before timer overshoot (excluding the separately reserved terminal pulse). This planning field survives reset. Live braking subtracts actual acceleration pulses from that full target. Previously the target was reconstructed from the halfway threshold plus the simulated braking remainder, losing any simulated acceleration overshoot. Manually constructed plans without this field retain the legacy budget fallback.

The deterministic external-tick regression covers both +33 and -33 degrees with a 5-ms timer: simulated acceleration has 74 pulses against a 73-pulse halfway threshold, whereas live acceleration has 73. Execution now retains all 147 target pulses including the terminal pulse instead of finishing at 146. The correction repairs the pulse budget; it does not change the last PWM period or the scheduler interval. Reported runtime pulses remain model estimates, not independently measured physical edges.
