# Hardware PWM and documentation corrections

`GpioMode::hardwarePwm` explicitly selects dedicated hardware PWM. RANGE, DUTY, frequency, and logical ON/OFF use the existing setters; read/write are rejected in this mode. RPI4 uses pigpio hardware PWM, RPI5 uses RP1 PWM0 through Linux sysfs and validates live Device Tree pin routing. Hardware channels remain reserved while logically OFF. Desktop simulates the RPI4 channel layout.

The full current behavior and limitations are documented in [gpio/PWM.md](gpio/pwm/PWM.md). `PwmSysfs` owns only channels it exports; `PwmSysfsIo` provides an injectable transport. `Rpi5PwmSysfsIo` implements native I/O and controller/pin discovery. `gpioHardwarePwmChannel()` maps a GPIO to a channel for an explicitly selected platform layout. New abstraction errors are NOT_SUPPORTED, CHANNEL_BUSY, and PWM_NOT_CONFIGURED; native sysfs failures use negative errno.

Corrections to the earlier hardware supplement: PWM setters now accept OUTPUT or hardwarePwm. Hardware OFF holds zero duty with the controller enabled; releasing it does not promise a LOW pin. `hardwarePwmChannel()` returns a channel number, not the ordinary zero-on-success status. Test constants are currently in hardware.h, not gpio/_defines.h. The restored gpio/_probes/gpio_probe.cpp blinks PIN_STEP/PIN_DIR/PIN_ENA and does not execute the PWM/inversion demonstration described by the earlier supplement.

`pwm_sysfs_test` runs entirely without hardware. GPIO_SYSFS_TEST enables the sysfs implementation for tests using temporary files; normal Raspberry Pi code remains guarded by SYSTEM_IS_RPI5. Existing contract tests always use the desktop implementation, including hardware-mode tests.
