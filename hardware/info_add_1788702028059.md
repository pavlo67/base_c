# GPIO mode switching and test cleanup

This supplements hardware/info.md and corrects the older GPIO test descriptions in info_add_1788642380974.md and gpio/pwm/PWM.md.

Repeated `setMode(pin, GpioMode::output)` stops active software PWM, drives LOW, and preserves range, duty, and frequency. Stop failures are returned to the caller. Without active PWM, repeating OUTPUT preserves the digital level. Repeating `hardwarePwm` preserves its existing behavior; switching to a different mode stops active PWM and releases the old mode through the backend.

All tests in `gpio/gpio_test.cpp` use the `GpioTest` fixture. Setup initializes the backend and configures GPIO_TEST_PINS from hardware.h as outputs. The saved levels are read after OUTPUT configuration and are used only by the digital inversion test; original pin modes are neither read nor restored.

Teardown attempts to switch every pin involved in the test to INPUT, then terminates the backend. It includes the hardware PWM pins in the hardware-mode test, continues after individual cleanup errors, and handles partially completed setup and a backend terminated by the lifecycle test. Failed initial initialization does not trigger pin changes. INPUT is the requested cleanup mode; backend errors are reported as test failures.

The hardware-mode conflict test uses GPIO12/18 on RPi4 and desktop, or GPIO14/18 on RPi5, plus GPIO13 and the unsupported GPIO17 check. It runs against the selected backend, so on Raspberry Pi it requires appropriate hardware PWM configuration and access. The current hardware/CMakeLists.txt has gpio_contract_test disabled; gpio_test includes digital, PWM, lifecycle, and channel-mapping checks.

The regression test checks that repeating OUTPUT after PWM permits digital writes, disables PWM without losing settings, and still preserves a digital HIGH when OUTPUT is repeated without PWM. Desktop tests verify API state and simulated levels, not physical waveforms or Raspberry Pi cleanup behavior.
